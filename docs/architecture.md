# 架构说明

## 一句话

**一个纯函数的决策核心 + 两个薄薄的平台外壳**：核心库只做"文本 → 决策"的映射，平台外壳负责摄像头、安装检测和跳转。

```
        ┌──────────────────── PC 端 ────────────────────┐
        │  login-qr.html：展示二维码（服务端生成）        │
        └──────────────────┬────────────────────────────┘
                           │ 用户用手机扫屏幕
                           ▼
   ┌──────────────────── 手机助手 App ─────────────────────┐
   │  CameraX 取流 → ML Kit 解码 → 得到一段文本            │
   │            │                                          │
   │            ▼                                          │
   │   ┌──────────────────────────────┐                    │
   │   │  QrParser   （纯函数，无 IO）  │  ── 拒绝 ──┐      │
   │   └──────────────┬───────────────┘            │      │
   │                  ▼                            │      │
   │      LoginTarget{platform, loose, host}       │      │
   │                  ▼                            │      │
   │   ┌──────────────────────────────┐            │      │
   │   │  AppInstallProbe（平台相关）   │            │      │
   │   └──────────────┬───────────────┘            │      │
   │                  ▼                            ▼      │
   │   ┌──────────────────────────────┐   ┌──────────────┐ │
   │   │  LoginRouter （纯函数）        │──▶│ Decision     │ │
   │   └──────────────────────────────┘   └──────┬───────┘ │
   │                                             ▼         │
   │                        唤起 App / 引导下载 / 手动提示   │
   └───────────────────────────────────────────────────────┘
                           │
                           ▼ 用户在官方 App 内扫码并确认
```

## 模块职责

| 模块 | 职责 | 输入的敏感度 | 是否联网 |
|---|---|---|---|
| `QrParser` | 清洗文本、判定 scheme、提取 URL host、匹配白名单 | 接触二维码原文 | 否 |
| `RuleSet` | 加载规则表、最长后缀域名匹配、denylist、凭据参数名识别 | 只读规则 | 否 |
| `AppInstallProbe` | 查本机是否装了目标 App，返回三态 | 只读本机包列表 | 否 |
| `LoginRouter` | 把识别结果 + 安装状态映射成 `Decision` | 只拿到平台枚举 | 否 |
| `Decision` | 给 UI 的最终指令（动作、文案、步骤、常量深链） | 不含凭据 | — |

设计要点：**敏感数据（二维码原文）只在 `QrParser` 内部停留一瞬**，越过这一层之后流动的只有平台枚举和布尔标记。这样 UI 层、日志层、埋点层都不可能泄漏票据。

## 解析流水线（为什么是这个顺序）

1. **清洗**：去零宽字符/BOM（`\u200b-\u200f`、`\ufeff`）、NFKC 归一化（全角冒号、全角句号）、去尾部中文标点。
   —— 防的是"看起来像域名的人眼视觉绕过"。
2. **scheme 闸门**：内容若以非 `http(s)` 的 scheme 开头，直接拒绝。
   —— 防的是二维码里塞 `weixin://dl/...` 这类跳转载荷。
3. **URL 提取 + host 匹配**：取第一个 URL 的 host，做**最长后缀**匹配。
   —— `login.weixin.qq.com` 同时命中 `qq.com` 和 `weixin.qq.com`，取更长者 → 微信，避免 QQ 误判。
   —— host 命中 denylist（`v.qq.com` 等）一票否决，防止把腾讯视频二维码当 QQ 登录码。
4. **URL 存在但不在白名单 → 直接拒绝**，不回退文字匹配。
   —— 否则 `https://evil.example.com/?next=wx.qq.com` 会被宽松放行。
5. **完全没有 URL 时才做 loose 匹配**：url_keywords → 裸域名 → 中文别名，且要求文本含扫码/登录语境词。
   —— loose 结果 `loose=true`，路由层**禁止自动跳转**。
6. **凭据标记**：只把 query/fragment 里的参数**名**拿去和 `credential_params` 比对，得出 `has_credential` 布尔值；值立即丢弃。
7. **指纹**：对原文做加盐 SHA-256 取前 12 位，用于排障日志关联；不可逆，且盐值写死在代码里，防止低熵二维码被彩虹表反查。

## 决策表（router 的唯一真相）

| target.loose | install status | action |
|---|---|---|
| true | 任意 | `manual_scan`（只提示） |
| false | INSTALLED | `open_app` + 常量深链 |
| false | NOT_INSTALLED | `prompt_download` + 商店链接 +（如有）密码登录兜底 |
| false | UNKNOWN | `manual_scan` + 商店链接 +（如有）密码登录兜底 |
| — | 解析失败 | `reject` / `manual_scan`（按拒绝原因） |

## 两端共享规则表

`core/platform_rules.json` 同时被 Python 核心库和 Android 端读取：

- Android 在 `build.gradle.kts` 里把 `core/` 加进 `assets.srcDirs`，运行时解析同一份 JSON；
- 因此新增平台/改 denylist 只需改一处，两端行为一致，不会出现"PC 上演示是对的、手机上判成别的平台"。

## 安装检测的三态语义

`INSTALLED` / `NOT_INSTALLED` / `UNKNOWN` 三态是刻意的：

- 把"查不到"当成"没装"，会让用户被引导去下载一个已经装好的 App（体验事故）；
- 把"查不到"当成"装了"，会让用户点了个唤起按钮却什么都不发生（体验事故）；
- 因此检测能力受限时返回 `UNKNOWN`，由路由层降级为"手动打开 App"的提示。

桌面端用 `shutil.which` + 常见安装路径（best-effort）；Android 端用 `PackageManager.getPackageInfo` + `<queries>` 声明。
